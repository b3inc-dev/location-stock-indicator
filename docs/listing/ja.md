## 4. 詳細（500 文字まで）

```
複数の店舗や倉庫がある店のためのアプリです。商品ページに、選ばれているバリエーションの在庫を店舗ごとに表示します。バリエーションを変えると、表示も切り替わります。

在庫は「在庫あり」「残りわずか」「在庫なし」の印や数で表示できます。印の境目と文言、表示する店舗、店舗の表示名と並び順は管理画面で決められます。配送やローカルデリバリーに対応している店舗を先に並べることもできます。

Pro プランでは、店舗をエリアごとにまとめて表示したり、お客様の現在地からいちばん近い店舗を表示したりできます。店頭受け取りができる店舗には、商品をカートに入れる受け取りボタンを出せます。表示とボタンの回数は日ごとに確かめられます。

テーマエディタで商品ページにブロックを足すだけで使えます。テーマのコードは書き換えません。
```
（356 文字。空白と改行も数えた）

## 5. 店にとっての良いところ

1. 「どの店にあるか」の問い合わせが減る【推測: 効果の数字は出さない】— お客様が商品ページで店ごとの在庫を見られる。
2. 店へ足を運ぶきっかけになる — 近い店舗と、受け取れる店舗が分かる（Pro）。
3. 見せ方を店に合わせられる — 印・文言・並び順・表示する店舗を管理画面で決める。
4. テーマを書き換えない — テーマエディタのブロックを足すだけ。

（1 の「減る」は効果の約束に読める。リスティングに使うなら「お客様が商品ページで確かめられます」までにする。）

## 9. 料金

### 9.1 決まっていること【事実】

- 料金は Shopify App Pricing（Partner Dashboard でプランを作る）。アプリは Billing API で契約を作らない（T の決定 2026-11-21、location-stock-indicator#49。作りは PR #48）。
- Pro は月 $20 ＋ 1 ロケーション $2。$2 の分は使用量（メーター `pro_location`）で、アプリが App Events API で 1 請求期間に 1 回送る（PR #50）。Shopify 側に上限（cap）は無い。
- 契約していない店では、商品ページに在庫を出さない（App Proxy が `plan_required`）。管理画面はホームと料金プランへ回す（`planGate.js`）。

### 9.2 プラン

| プラン（表示名） | 月額 | ロケーション | 無料体験 | 使える機能 |
|---|---|---|---|---|
| Lite | US$20 | 10 か所まで | 7 日 | 店舗別の在庫表示・印と境目・表示する店舗・表示名・並び順・リンク |
| Pro | US$20 ＋ 1 か所 US$2 | 制限なし | 14 日 | Lite のすべて＋エリア・近い店舗・受け取りボタン・分析 |

- 無料体験の日数は T さんの決定（2026-11-22、#49）: Lite 7 日・Pro 14 日。App Pricing では Partner Dashboard に入れる値が正になる（[partner-dashboard-steps.md](partner-dashboard-steps.md) 1 章に同じ値を書いた）。
- Lite で 11 か所以上ある店は、管理画面を料金プランの画面へ回す（`locationPlanMismatch`。`app/routes/app.jsx`）【事実】。
- Pro の $2 の数え方: **すべてのロケーション数 × $2**（10 か所を引かない）【事実: PR #50 の `computeProLocationUsage`】。例: 5 か所 → $20 ＋ $10。

### 9.3 料金欄に書く「追加の料金」の文

```
Pro はロケーション 1 か所につき月 US$2 を、月額 US$20 に加えて Shopify の請求に載せます。請求期間ごとに 1 回、その時点のロケーション数で計算します。
```
- 【推測】App Pricing では、リスティングの料金欄はプランの設定から作られる。メーターの説明を入れる欄があればそこへ貼る。
- 「その時点の数」: PR #50 は管理画面を開いたときに数えて、請求期間に 1 回送る【事実: #49 のコメント「報告は管理画面からだけ」】。#50 が main に入る前に作りが変わったら直す。
